## 2. 五处真因与初判不同（团队纠错）

1. **圆点飘天**：不是「负偏移画错」，而是 **`_retarget()` 只对准「当前歌词行」**，而前奏 `_idx=-1` ⇒ 目标 0 ⇒ 圆点行被顶到面板 **2.24%**。
2. **闪烁不动**：改名后残留 `if act:`（未定义变量）⇒ 每帧 `NameError`、相位恒 0 ⇒ **闪烁整段根本没执行**。
3. **顶栏消失**：不是「hide() 没复位」，而是 **`QGraphicsOpacityEffect` 被 fade_out 动画到 0 后再没人复位**。
4. **滚轮到顶卡死**：`_scroll_bounds` 方向本来是对的；真因是 **`_refresh_focus()` 优先 `_hover_idx`** ⇒ 滚轮只改 offset、焦点锁死在鼠标停留行。
5. **全屏黑屏**：确认是 **DWM 独占翻转**（尺寸恰等于屏幕分辨率）⇒ 用**高度 +1px** 的 borderless geometry 绕过。

## 3. 方法论沉淀（本阶段最有价值的部分）

- **真机证据三原则**：① 屏像素必须 `primaryScreen().grabWindow(0)` 真实抓取（`QWidget.grab()` 不含父级 `QGraphicsOpacityEffect`，不能当证据）；② 用户机器 Chrome 在前台时 `SetForegroundWindow` 会被拒，需**临时 Qt 置顶**抬窗（方法调用、测完撤销并还前台）；③ 图标掩膜必须先排除底板/内环（饱和度+最大连通域），否则把底板量成 210×210。
- **写状态只走方法调用**（`zhjctl eval` 只吃表达式，赋值被静默丢弃）—— 已从第八阶段延续为纪律。
- **测量口径要先自证**：本阶段 QA 三次「假 FAIL」全部来自挂具（读失效键、跨句窗口、中值过零除以 2），每次都由 Lead 给出正确口径后 1 分钟内澄清。
- **开工前清场**：收口前发现 **25 个 zhj* 残留测试实例**（python.exe），全部清理后才跑打包版复验 ⇒ 读数不受污染。

## 5. 已知边界（如实登记）

1. **无带人声的真实素材** ⇒ 判据「人声突入」用 **−40→−12dB 受控阶跃**等价模拟（QA 另用真实音乐稳态交叉）；
2. **振幅加权交替率持平**（0.571→0.556）—— 该指标对任何平滑波本就约 0.5，**不是缺陷**；用户看到的「梳子」已由「空间锯齿度 −30% + 逐帧 Δh ≤0.08」压住；
3. **`spectrum_state()` 尚无 `corr` 键** ⇒ Dev 的 `r_p05` 与 QA 自算值不同源（并列不冲突）；
4. **Alt+Tab / 窗口拖拽** 在 QA 侧因 UIPI/前台限制无法注入验证（Dev 侧实测通过）；
5. **全屏耗时** QA 实测 30.36/35.33ms（Dev 12.6/11.4ms）⇒ 计时边界不同，**主判据（近黑帧 0 / 累计 90 帧）不受影响**；
6. **15s 句间门槛**后多数歌曲不再出现句间圆点行（用户明确要求「只在长间奏出现」；如需调整只改 `IL_GAP_TRIGGER_MS` 单常量）。
