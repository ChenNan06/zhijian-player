## 一、4 项 P0 回归 / 缺陷的真因与修法

### ① 窗口模式打开视频，底部控制栏完全不显示（问题 1）

**排查过程**：先按卡面假设查了 `capsule_host` 布局、`raise_overlays()`、fader 透明度 —— 全不成立。**真因是平台级**：

> mpv 画布是 `QOpenGLWidget`，在 Windows 上会创建**原生子窗口（native child window）**，而原生子窗口**永远绘制在非原生兄弟控件之上** —— 控制栏无论怎么 `raise_()` 都会被视频盖住。

**A/B 实证**（同一实例、同一鼠标位置、fader 不透明度 = 1.0）：

| 视频占行 | 底部区域「灰比」 | 结论 |
|---|---|---|
| 4 行（与控制栏重叠） | **0.048** | 控制栏被盖住 |
| 3 行（让出底栏一行） | **0.157 / 0.159**（两次） | 控制栏稳定可见 |

**修法**：`stage.set_video_row_span()` 作为唯一入口 —— **窗口视频模式 3 行（底栏独占一行）、全屏保持 4 行叠加**；`_sync_video_row_span()` 挂在 `_wake_ui()` 与 `toggle_fullscreen()` 末尾；`_wake_ui()` 补齐 **fader 不透明度硬复位**（`fade_in()` 在 `_visible=True` 时会直接 return，中断的淡出会永久停在 0）+ `capsule.show()` + `raise_overlays()`。

**实测**：冷启动直接开 MP4 ⇒ 底栏灰比 **0.157**、亮点像素比 0.0069、`_video_rows=3`；进出全屏 4↔3 正常；**QA 用真实 `SendInput` 复验 Tooltip「暂停 (Space)」(88×28) 与进度条缩略图预览 (160×113, 含 `00:11`)** 均正常弹出。

**取舍（如实）**：窗口模式下视频区因此**矮 94px**。这是绕过「原生子窗口永远在上」的确定性做法；若要求底栏浮在画面上，需把底栏改成独立顶层浮窗 —— 代价与风险都过大，本阶段不做。

### ② 图片模式莫名变成「绿色强调色」（问题 4）

**真因**：上一阶段只给旧主题标了 `deprecated`、**没有物理删除**；某处按索引遍历或异常回退时命中了绿色 `mint`。

**修法**：**物理删除** `graphite / qq-light / qq-dark / amber / sakura / aurora / mint` 七套配色字典，`THEMES` 只剩 `glass-light`(#2080FA) / `glass-dark`(#3898FF)；`LEGACY_THEME_MAP` 只保留字符串映射（旧名仍能无感迁移，但绝不回退旧配色）。

**实测**：图片模式 6 张整窗图 **UI 区绿像素 0/0/0/0/0/0**；`#10B981` / `#00C48C` / `#5BD98A` grep **0**；`mint` 仅剩兼容映射；`THEMES` 键数 **2**。

### ③ 标题栏与背板要「QQ 级桌面实时高斯模糊」（问题 3）

**用户澄清**：此前批评「标题栏随**视频内容**变色」，不是要死白实心块 —— 要的是**根据窗口背后的桌面壁纸/其它窗口**做实时高斯模糊。

**修法**：`win.py` 新增 `_dwm_extend_frame(-1)` + `DWMWA_SYSTEMBACKDROP_TYPE=3`（亚克力），并提供 `set_acrylic_lite` **拖动降级 API**（保证 144Hz 跟手）；`titlebar.py` 不透明度 **0.82 → 0.30（浅）/ 0.36（深）**，不再绘任何不透明底板；`main_window` 玻璃皮肤下强制 `WindowBody/TitleBar` 半透。

**实测**：`_acrylic_on=True`、`_dwm_extend_frame=True`、`TITLEBAR_LIGHT_RGBA=[245,248,255,77]`（0.302）、`DARK=[18,22,30,92]`（0.361）、拖动降级可逆；播放中标题栏连续 **5 帧 max_diff = 0**（不随视频变）。

**如实边界**：本机共享桌面被占用，「彩色壁纸光晕 + 拖动实时跟随」的**视觉对照未能取证**（QA 的受控底窗被其它窗口盖住）。实现锚点与「不随视频变」已证。

### ⑦ 宽屏音瀑彻底重做：全曲预扫描谱面 + 毫秒卡点 + Phigros 级特效（问题 6）

**旧实现的致命问题**：实时检测到声音才生成音符，等落到判定线已经晚了 1 秒多。

**新架构（两个新模块）**：

1. **`media/beatmap.py`（纯标准库 —— 运行环境无 numpy）**：后台线程 ffmpeg 读单声道 PCM ⇒ **四频段**（20–130 / 130–500 / 500–2800 / 2800–8000Hz）短时能量一阶正向差分 ⇒ 滑动窗 `LocalMean + 1.4×Std` 自适应阈值取峰 ⇒ **三点抛物线亚帧化** `t_hit`（精度 ~1–2ms）⇒ 三类音符 **TAP / DOUBLE(±25ms 双频同时) / HOLD(能量平台 ≥450ms)**；
2. **`ui/rhythm_stage.py`**：`T_fall = 0.85s`，`y = y_judge − (t_hit − t_now)/T_fall × (y_judge − y_top)`，**解析穿越判定**；时间源优先 `playback-time` + **PLL 锚点插值**（帧内插值、0.25s 跳变重置、暂停不插值）；
3. **视觉**：4 轨微透视 + 判定线随低频呼吸；TAP 冰青 `#00E5FF` 白核、DOUBLE 黄金 `#FFD700`、HOLD 头部胶囊 + 渐变长尾；命中 **Keybeam 光柱(150ms) + 菱形扩散波纹 + 6 颗粒子(220ms) + `COMBO × N`**。

**实测**：`n_events=432`（TAP 245 / DOUBLE 187）；**`dev_ms_analytic_mean = 0.0`**（三组独立采样：78/132/147 hits 全 0.0）；`frame_quant_mean 13.26ms`（16.7ms 单帧物理上限内）；合成长音素材 `hold_test.mp3` ⇒ **4 个 HOLD，dur 1.98s**；QA 4× 图确认 TAP/DOUBLE/HOLD 长尾/Keybeam/菱形波纹/**6 颗粒子**/`COMBO × 149`；seek 12s 后仍对齐；QTimer 2 / frame 16ms 不回归。

**已知边界**：解码+打分 0.29–0.37s（卡面要求 0.2s，超）；`frame_quant max ≈ 49ms` 为起播/seek 瞬态；无长音素材时 HOLD=0（语义正确）。

## 三、本阶段最有价值的两次「复核员追上真 bug」

### ① 切歌不重建谱面 —— 追出「异常被吞」的老病

QA 发现：切歌后 `rhythm_debug()` 仍是旧曲谱面。逐层追查后根因是：

> `audio_view.py` 换文件分支调用 **`self.rearm_energy(...)`**，但 **`AudioView` 根本没有这个方法**（它属于 `SpectrumWidget`）⇒ 运行时 `AttributeError` ⇒ 被紧随的 **`except Exception: log.debug(...)` 静默吞掉** ⇒ 后面的 `_start_beatmap()` 永远不执行。

**修法**：① `self.spec.rearm_energy(...)` 指向真正的持有者；② `_start_beatmap()` 提到独立 try；③ 吞异常一律升级为 **`log.warning(..., exc_info=True)`**。
**实测**：`cmd=open(hold_test.mp3)` ⇒ **自动** `gen=2 / n=20 / holds=4`；切回 ⇒ `gen=3 / n=432`；快速双切 ⇒ 旧 worker 结果不污染（gen 递增）。

> 这已是本项目第 N 次栽在「`try/except` 里 `log.debug` 吞异常」上。已立规矩：**吞异常必须 warning + exc_info**。

### ② 切歌后 COMBO 延续上一首

QA 从截图细节发现新曲 t=0.36s 就显示 `COMBO × 251` ⇒ `RhythmStage.set_events()` 没重置按曲状态。修法：换谱时归零 `_combo / _hit_flash / _pulse / _devs* / _seen / PLL 锚点`。实测三曲连切：`combo` 从 0 重新计数 ✓。

## 六、方法论沉淀（本阶段 4 条）

1. **`QOpenGLWidget` 原生子窗口是「浮层被盖住」的总根源** —— Windows 上它永远在非原生兄弟之上，`raise_()` / `WA_AlwaysStackOnTop` 全部无效；解法是**布局让位**或**独立顶层窗**；
2. **吞异常必须 `warning + exc_info`** —— 本项目已有多起「功能静默失效」源于 `except: log.debug(...)`；
3. **指标口径要拆开** —— 音瀑偏差拆成 `analytic`（谱面/穿越精度）与 `frame_quant`（帧显示上限）；列表性能拆成**增量**而非绝对值；否则会把物理上限当成实现缺陷；
4. **「验不到」必须落成书面未取证** —— 本阶段两次未取证都追出了真 bug（切歌不重建谱面、COMBO 不重置）。
