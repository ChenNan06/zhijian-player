## 2. 本阶段挖出的五个真根因

1. **手柄被歌词吞**：抽屉展开后手柄坐标落进底层歌词面板矩形，而 task-41 的事件过滤器**没有遮挡守卫** ⇒ 点击被截胡、光标卡死。
2. **外部双击无反应**：单实例守卫只做了互斥、**没有把新进程的文件参数投递给主实例**。
3. **前奏提前高亮**：task-44 的「首句预选」rider 与用户的「前奏零误选」直接冲突（本阶段按用户口径推翻）。
4. **频谱看不出强弱**：`SPEC_LEVEL_DB=(-60,0)` + 两条感知放大 = **保底自嗨振幅**，轻音与重音都被顶到同一平台。
5. **冷启动主题图标反了**：`on_theme_changed()` 只重绘、不设图标；真正设图标的是 `set_light()`，而启动路径没调它。

## 3. 协作与门禁

- **并行分工**：A 链（audio_view + main_window）与 B 链（app/ipc/settings/win/assets/scripts）**写域不相交**，同时推进。
- Lead 本阶段 **9 次口径裁决**：胶囊目标澄清（非 ProgressSlider）、间奏点亮方向、光标分模式、宽屏 25–30% 仅在 content_w 封顶时成立、基准封面 310→320 属预期、装饰环影响阴影剖面、深色档投影保留、黑胶直径 48→44 属本卡反转、−40dB 单样本越界记已知偏差不开新修订。
- **最有价值的工程发现**：`zhjctl eval` **只接受表达式**，赋值语句被**静默丢弃** ⇒ 所有「写状态」的探针必须走方法入口（本轮据此新增 `spec.set_inject()` / `ly.set_inject_position()`）；这条解释了此前多张卡的「假 FAIL / 短路无效」。
- **QA 与写手的自我更正**：QA 撤回「疑似挂起」（实为长 eval + 漏带 `--no-single-instance`）、撤回「主题图标路径问题」（实为真 bug）；Dev-3 公开更正两次误判（注入过冲 / 链路未调 set_light）；Dev-4 主动报既有 `at_cursor` 缺陷。
