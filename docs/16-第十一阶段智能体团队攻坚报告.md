## 2. 三个「看着丑」的根因（本阶段真正的收获）

1. **假截图模态**：task-71 用「抓一帧静态图 + 离屏模糊 24 + 噪点」做模态背板 ⇒ **画面定格 + 颗粒**，用户以为播放器卡死。根治：**删掉抓图路径**，只留一层平滑暗化 ⇒ 底层视频实时渲染。
2. **按钮文字被盖**：task-72 在按钮 `paintEvent` **最后又叠了一层上半截白块/渐变** ⇒ 文字被切。根治：**先底后字**的标准绘制顺序 + `minimumWidth = advance + 36`。
3. **切肤白块**：玻璃窗口 `WA_TranslucentBackground` + 顶层 `WA_NoSystemBackground` ⇒ 子控件局部重绘**不擦上一帧**，上一主题的白色按钮底残留。根治：**显式透明属性 + `paintEvent` 完全自绘（禁 `super()`）**。

## 3. 方法论沉淀（本阶段 6 条，已入 `review_baseline.md`）

1. **鼠标唤醒/悬停**类判据必须用 app 内 `QTest.mouseMove`；`QCursor.setPos` 只移系统光标 ⇒ 假阴性（曾误判「标题栏不可见」，实为沉浸自动隐藏的设计行为）。
2. **「底层是否在动」只能用连续帧像素差** —— `playing=true` 在 bug 态也是 true（用户就是被骗在这）。
3. **白墨 + 透明底图标放大前必须合成深底**，否则全白看不见。
4. **拖动类判据每步之间要 `processEvents`**，否则驱动不动。
5. **跨 DPR 比形状**只能降采样 + 容差；**两臂数值逐位相同 ⇒ 口径无效**（正确自检信号）。
6. **屏幕级截图会被外部置顶层污染**：本轮那块「绿色方块」经像素指纹（**#76B900 精确 7540 px**）+ 窗口枚举（`CEF-OSC-WIDGET`）定性为 **NVIDIA GeForce Overlay HUD**，与产品无关；验证本产品 UI 一律用 `w.grab()`/PrintWindow。

## 5. 已知边界（如实登记）

1. **打包版不含 `PySide6.QtTest`** ⇒ 任何依赖 QtTest 的旧门禁 snip 在打包环境会 import 失败（本轮首轮 2 条 FAIL 即此，复测用 `drawer_edge_state()` 直读通过）；建议后续门禁改外部事件注入或把 QtTest 打进包。
2. **全屏（AV 1707 宽）封面占比 0.7721**，比 task-34 下限 0.78 低 0.0079 —— 是 `COVER_MAX_HARD_PX=420` 与 task-46 `CONTENT_MAX_W=1600` 的**既有交互**，**非本阶段引入**，记为观察项。
3. **图标形状 IoU 最差 0.9325**（moon@1.5）—— 2px 细描边在 24px 网格上的 ≤0.5px AA 位移；**明确裁决：不为过阈值加粗描边**（几何 bbox/质心才是硬判据）。
4. **玻璃标题栏对比度**在纯白壁纸极值下 4.94:1（略高于 4.5 下限，余量不大）；若后续觉得不够，继续加深标题栏底而不是加回文字衬影。
5. **菜单关闭后窗口级蓝像素**判为 hover 高亮（非缺陷），但**探针在光标不移开时会看到恒定蓝值** —— 后续复验必须先移开光标。
6. **task-82 的陈旧残留机制**仍保留防御性修复（`CompositionMode_Source` 真擦除 + 四段延迟擦净），未在真实用户路径复现过残留，属防御性代码。
