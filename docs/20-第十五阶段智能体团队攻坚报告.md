## 一、8 处真机缺陷的根因与修法

### ① P0 玻璃模糊只铺左上 2/3（问题 3、8）

**现象**：150% 缩放下，设置面板与播放列表的模糊背景只覆盖左上 **66.7% × 66.7%**，右侧 1/3 与底部 1/3 露出锐利视频。

**真因**：**物理像素与逻辑像素混用** —— `grabFramebuffer()` / `QPixmap.grab()` 得到的图带 `devicePixelRatio = 1.5`，被当成逻辑尺寸使用 ⇒ 逻辑尺寸只剩 `1 / 1.5 = 66.7%`。

**修法**：三条抓帧路径 + `_blur()` 输出 + temporal blend + resize 拉伸缓存**全部 `setDevicePixelRatio(1.0)`**；`paint_backdrop()` 源矩形按「逻辑 ÷ 6」计算并**显式目标矩形**绘制，再兜底归零一次。

**实测**：`plate_dpr = 1.0`（修复前 1.5）｜面板四边高频残差 左 0.089 / 右 0.116 / 上 0.211 / 下 0.320（面板外锐利视频跳变 **123**）⇒ 右 1/3、下 1/3 均有模糊、**无断层**｜抽屉 左 .310 / 右 .266 / 下 .281。

### ② P0 标题栏随视频内容变色（问题 2、3）

**真因**：标题栏在视频上方、并不遮挡视频，却被设计成采样视频顶部像素做模糊 ⇒ 画面一变标题栏就忽白忽灰忽黑。

**修法**：**删除全部采样代码**（`_paint_viewport_tint()` 移除，`GlassBlurPlate` 引用 grep 0 残留），改为恒定材质：

- `glass-light`：`TITLEBAR_LIGHT_RGBA = (242,245,250,209)` = **rgba(242,245,250,0.82)** + 底部 1px 柔和分割线；
- `glass-dark`：`TITLEBAR_DARK_RGBA = (24,28,36,209)` = **rgba(24,28,36,0.82)**；
- 顶部 1px 高光同样恒定。

**实测**：播放中连续 5 帧同点色差 **max_diff = 0**；平均色稳定 (239,243,248)；换肤 light→dark 100ms 内 Δ144（立刻变深）。

### ③ P0 设置界面右侧整块纯白（问题 1）

**真因**：task-107 的 `_merge_pages()` 新建容器与 `QScrollArea.viewport()` **未设透明背景** ⇒ 被系统默认 `QPalette.Window` 刷成实心纯白。

**修法**：面板内**所有** `QScrollArea` / `viewport` / merge 容器 / `_card` 强制 `WA_TranslucentBackground` + `setAutoFillBackground(False)` + `background: transparent`（**43 个容器**统一透明）。

**实测**：整页纯白占比 **21.81% → 0.74%**（抽屉 **0.0%**）。

### ④ 滚动区上下边缘 Alpha 羽化（问题 2）

**修法**：新增 `ScrollFeatherEffect`，对设置面板 7 个滚动区与播放列表抽屉施加 **上下各 28px** 的 `CompositionMode_DestinationIn` 垂直线性 Alpha 遮罩（顶部 0→255、中部 255、底部 255→0），**离屏缓冲乘 `devicePixelRatioF()`** 保文字锐利。

**实测**：顶部首行「1 bilingual_jp.mp3」明显变淡、底部 12~14 行逐行渐隐至消失；亮度剖面单调无硬切；文字笔画清晰。

### ⑤ P0 看图模式黑屏（问题 9）

**现象**：进入看图模式完全黑屏，只有滚轮缩放瞬间画面才闪现，滚轮一停又黑。

**真因**（代码级锁定）：`GlassBlurPlate._grab_stage()` **每 33ms** 对图片视口调用 `iv.grabFramebuffer()`。图片视口自己就是 `QOpenGLWidget` —— 在它自己的上下文里反复绑 FBO 读回，把视口 FBO 的内容读没了：静置时没有新 paint ⇒ 黑屏；缩放时弹簧定时器每帧 update ⇒ 立刻闪出。

**排除项**（逐项实测）：加载正常（`_img` 1898×1068、`has_image()`=True）、几何正常（`image_rect=(6.33,0,1265.33,712)`）、非透明/主题问题（关 `WA_TranslucentBackground`、换主题全为 0）、非上下文问题（doneCurrent / makeCurrent / 隐藏显示 / resize 全无效）。

**修法**：图片分支**不再读 GL**（`return None`，`_source="image-none"`），浮层回退上一帧缓存纹理 / 纯半透玻璃底；`stage.set_image_mode()` 进图片模式**先** `video.hide() + setUpdatesEnabled(False)`；`_iv_load()` 前后再 hide + 强制重绘。

**实测**：静置 **10 帧 × 200ms 中央 luma 44.2 恒定**（>30）；滚轮中 46.6、停止 2s 后 44.2；浮层打开不黑；视频模式 `_source=video-gl` 不回归；QTimer 2。QA 独立复验：静置 10 帧 luma **87.6** 恒定且与原图逐通道差 **0.2/765**。

### ⑥ P0 音乐切视频闪一帧放大封面 + 切后滚轮调不了音量（问题 6）

**真因①**：`open_path()` 在 `engine.load()` **之前**就 `_apply_kind_ui(VIDEO)` + `engine.set("vid","auto")`，此时 mpv 仍载着上一首 MP3 ⇒ `vid=auto` 让它把**内嵌封面**解码画到 video 上。

**真因②**：歌词的应用级滚轮过滤器在非音乐模式仍消费事件 ⇒ 视频模式滚轮被当歌词滚动吞掉。

**修法**：切视频序改为 ① `engine.cmd("stop")` 清旧流与封面帧 + `hide()` 视频；② `engine.load(...)`；③ `_show_video_when_first_frame()` 以 **`video-params/w`** 为首帧就绪判据（40ms 复查 ×12 兜底）再 `show()`。滚轮改由 `_sync_audio_wheel_filter(kind)` 按模式装卸。

**实测**：逐 30ms 采样 24 帧，「video 已可见但参数未就绪」**= 0 帧**；音量 **100→95→90→85→80** 双向单调；首帧 ~370ms。QA 独立复验：切换序列 = 音乐界面 → **均匀空画布（非封面）** → 视频，无封面二次尖峰。

### ⑦ P0 最大化拖拽还原后四角仍直角 + 四周 1px 描边（问题 4）

**真因**：系统拖拽还原**不经过** `toggle_maximize()`，只触发 `changeEvent(WindowStateChange)` 与 `resizeEvent()`；原代码未在这两个事件里同步 ⇒ `isMaximized()` 已 False 但 DWM 仍 `DWMWCP_DONOTROUND`（直角）、`#WindowBody` 仍按最大化处理（1px 描边）。

**修法**：新增 `_sync_max_restore()` 挂 `changeEvent` + `resizeEvent`，以**真实 `isMaximized()`** 为唯一真源：最大化/全屏时去掉 1px 描边 + 圆角 + 边距；回普通窗口时**立即** `enable_rounded_corners + set_window_border + apply_dwm_round_corners(True)` 并同步最大化按钮图标（`_win_state_cache` 防每次 resize 重复调 DWM）。

**实测**：还原后 `_dwm_ok=True`、四角与内圈差 **34.6~376.1**（8× 图弧线清楚）、四边 2px 带**纯白 0.0000**、按钮图标 max→restore→max 同步。

### ⑧ 译文歌词换了字体（问题 5）

**用户原话**：「翻译歌词里居然是楷体，太细了，不符合原文字体风格！」

**修法**：译文回退栈**移除 KaiTi / FangSong / SimSun**，改 **YouYuan → Microsoft YaHei UI + 字重 Medium(500)**；译文行自动包 **`「」` 直角引号**（**折行前**包裹，算进宽度与断点）；`LYRIC_TRANS_RATIO 0.76 → 0.78`；原句保持 HarmonyOS Sans SC（当前行 Bold 700 / 未唱 DemiBold 600）。

**实测**：本机无幼圆 ⇒ 生效 **Microsoft YaHei UI / 500**、译文 **21/16px**、主词 700/600；日/韩 4 行译文全部「」包裹；浅色 `_shadow_main` 计数 **0/0**（零黑影）；超长译文折 3 行逐行宽 364/364/224 ≤ 面板 666px、逐字无缺。

## 五、已知边界（如实登记）

1. **羽化同时淡出滚动条上下端** —— `QGraphicsEffect` 作用于整个滚动控件是 Qt 技术限制；自绘滚动条属独立重构，收益（两端约 12px 略淡）远小于风险，**接受**；
2. **图片模式下浮层无实时动态模糊** —— 玻璃板保留进入图片模式前的最后一帧纹理或纯半透玻璃底，**不黑但也不随图片实时更新**；这是「不读坏图片视口 GL FBO」的既定取舍；
3. **16:9 素材在 16:10 屏的 letterbox 黑边** —— 正常播放器行为，**不做 fill/crop**（会裁画面）；
4. **任务卡面提到的 `_maximized` 字段在本仓不存在** —— 一直用 `isMaximized()` 实时判定，实现按真实状态；
5. **真实鼠标拖拽还原** —— 自动化多次合成拖拽未能触发系统 move loop，用 `SC_RESTORE` / `showNormal()` 同一 `WindowStateChange` 路径取证（缺陷判据已由四角/四边像素数据证明）。

## 六、方法论沉淀（本阶段 5 条）

1. **DPR 混淆类问题第一锚点 = `GlassBlurPlate.instance().stats()['plate_dpr']`**，**≠1.0 即坐标系混用**；
2. **动态属性/锚点写完立刻读回自证** —— `try/except` 里的 `setProperty` 变量写错会被静默吞掉，只有真读一次才暴露；
3. **UI 锚点的量程与运行时夹取必须同源**（从主题度量取 min/max，不写死常量）；
4. **「验不到」必须落成书面未取证，不许含混放过** —— 本阶段三次未取证逼出三个真 bug；
5. **夹具错误的自我识别** —— 译文字体像素差恒 0 时先怀疑夹具（无译文的 lrc），换双语 lrc 即见真实重排 3812/16574 px。
