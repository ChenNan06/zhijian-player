### 1.3 `dpi200` / `dpi150` 分支的真相（重要）

- **XML 里没有任何 dpi 条件分支**：不存在 `<If dpi=...>` 之类的结构，也不存在 `width_dpi200` 这类属性。
- 真实机制是**文件名后缀约定**：`skinDefault\skinplan\**` 下几乎每张 PNG 都有孪生文件 `xxx_dpi200.png`（本机统计：656 张里约一半带 `_dpi200`）。
- 例：`player/miniplayer/ctrl/play.png`（164×41）↔ `play_dpi200.png`；`list/list_bk.png` ↔ `list_bk_dpi200.png`。
- 加载器在检测到系统缩放 ≥150% 时把文件名替换为 `_dpi200` 版本，**XML 布局数值本身不变**（DirectUI 按 DPI 缩放整个布局树）。
- 本次截图运行在 **150% 缩放**下，因此实际渲染是 XML 数值 × 1.5，用的仍是 1× 切图（放大绘制）。这也解释了截图里图标略软。

## ⑦ 配色表

### 7.1 取色方法

1. **`theme.json` 全量解析**：512 个颜色键（skinDefault 257 / skinPeeler 255），原文为 8 位裸十六进制 `AARRGGBB`（无 `0x` 也无 `#`），全部换算为 `#RRGGBB` + alpha。
2. **皮肤 PNG 逐像素采样**（Pillow）：纯色底图直接取中心像素，多帧切图取各帧，带 alpha 的按 alpha 合成推算。
3. **运行截图逐像素采样**：在 10 张截图上按语义区域取点 + 区域众数（dominant）。

| 分割线 | `#1D1D1F` / `#272728` | **`rgba(255,255,255,.06)`** | 统一为半透明白，自动适配任何底色 |

| 字体阶梯 | 12 / 14 / 20（微软雅黑） | **12 / 13 / 14 / 16 / 20**，正文用系统 UI 字体栈 | 保留 12/14 两档主力 |

### 9.3 明确「不照搬」的几点（附原因）

| 原设计 | 为什么不照搬 |
|---|---|
| 控制条通栏、无圆角、无外边距 | 这是 2017 年前后的桌面播放器范式；现代播放器（IINA / Infuse / PotPlayer 新版）普遍用悬浮胶囊，让视频画面完整可见，观感提升最大。 |
| 进度条画在控制条**外面**（在控制条上沿之上 1px） | 导致「进度条属于谁」的归属感模糊，且拖动热区只有 3px 高。建议把进度条**放进控制条内部**（胶囊内顶部），热区扩到 12px。 |
| 三套互不相同的绿色（`#45B000` / `#00993D` / `#0BB005`） | 明显是不同时期模块各自加色造成的不一致，统一后品牌感更强。 |
| 抽屉用 1px 实线分割 | 现代设计用留白 + 圆角卡片区分层级，实线显得割裂。 |
| 设置分类栏选中态只有极淡的底色差（`#262629` vs `#1D1D1F`） | 对比度仅 ~3%，弱视用户难以辨识；建议加左侧 3px 强调色指示条。 |
| 列表项 32px 行高 | 在 4K/150% 缩放下文字 12px + 行高 32 显得空且密，44px 更符合现代触控/鼠标混合场景。 |
| 图片查看器用**浅色**主题（`#EDEDED` / `#F2F2F2`）而播放器用深色 | 同一产品内明暗主题割裂。建议图片查看器也走深色，或在设置里提供明/暗切换。 |
| `caption` 拖拽区比标题栏高 2px | 历史遗留，会与「双击标题栏最大化」的热区产生轻微歧义。 |

## 附录 B：如何验证本表的可靠性

任取一条数字都能用下式复算：**物理像素 ÷ 1.5 = 逻辑像素**。

例如「播放键绝对居中」：
- 截图实测圆左右外沿 = 物理 622 与 675 → 中心 648.5 → 逻辑 **432.3**
- 窗口宽 1299 物理 → 中心 649.5 → 逻辑 **433.0**
- 偏差 0.7 逻辑 px（≈1 物理 px，属抗锯齿范围）→ 结论成立。

再如「关闭按钮右对齐规则」：
