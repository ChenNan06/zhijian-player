## 1. 每张卡的真因与修法

### Task-01 手柄：三处独立病灶
1. `DrawerHandle` 用类常量 `W=20/H=74` 算绘制几何，而运行时被强制 `setFixedSize(16,56)` ⇒ 形状右/下被控件边界硬裁、箭头落在 (3,30) 而非真实中心 (8,28) —— 用户看到的「半截手柄」；
2. 填充直接实心 `P["glass_capsule"]`（graphite 下 #2B2F35FA，alpha 250）⇒「深黑实心底板」；
3. `Stage` 内**两份** `resizeEvent`（旧 915 被 1171 覆盖＝死代码），坐标算式散落在 4 处。

修法：新增模块级唯一真源 `HANDLE_W/HANDLE_H=16/56`；`paintEvent` 一律按 `self.width()/self.height()`；新增 `apply_handle_geometry()` 作**唯一** apply 入口（resize/抽屉开合/热点/模式切换全委托它）；删除死代码；填充改为半透明纵向渐变 + 1px 收边（浅色主题 `inner_glow` 全透明时退化到 `hairline`）。

### Task-02 封面：投影越界被硬裁
两层「圆角投影」的矩形是 `QRectF(x-grow+1.5, y-grow+3.0, side+2grow, side+2grow)`，`grow=7` 时右/下各超出控件 5.5/4.0px；**QWidget 画不到自身 rect 之外** ⇒ 被裁成直边，圆角外露出一截死灰直角。删除两层投影后绘制全流程只剩**一条** `addRoundedRect(12,12)`（同时作裁剪与 1px 描边路径），零 `fillRect/drawRect/fillPath`。

### Task-03 频谱：三条独立问题 + 一条 Lead 追加
1. `band = 0.30 + raw**0.5 * 1.35` 把柱体顶到饱和 ⇒「高度接近的蓝带」；改为 `x = raw/max(raw)` 帧内归一 + `band = 0.18 + 0.82·x^0.62` + 对数频段倾斜 `(F_HI/F_LO)^(-0.35u)`；
2. 暂停判定用 `_cur_pos > 0.05` ⇒ 中途暂停位置恒 >0.05 ⇒ 永远当在播；改为优先读 mpv `pause` 状态 + 位置停滞兜底，暂停时 `band -= 2.2·dt` 平滑归零；
3. 落峰写死 `4.0×(33/1000)` ⇒ 帧长一变速度就变；改为 `4.0×真实dt`（33ms 与 16ms 实测都是 −4.0px/s）；
4. **Lead 追加**：原公式 `spec_y = H-72-48-16` 实测与胶囊**实体**上沿是 **−4px**（柱底 4px 被盖住、柱基贴住控制栏，视觉零间隙）；改为从 `Stage.capsule` 真实几何推导 `spec_y = 实体上沿 − 48 − 16`（窗口 620−64=556、全屏 975−64=911，间隙均为 **16px**），用户给定公式保留为**胶囊不可用时的回落**，并把静默回落改成 WARNING 日志（R1）。

### Task-04 歌词与帧钟
- `FRAME_MS 33 → 16`。⚠️ 关键发现：33ms 在 Windows 15.625ms 系统 tick 网格上必须等 3 个 tick = **46.875ms**（实测 46.8ms / 21FPS），而 16ms 只占 1 个 tick ⇒ 实测 **15.7ms / 63.7FPS**。**不是代码慢，是定时器量化**。
- 绘制期测量清零：占位分支的 `p.fontMetrics().horizontalAdvance()` 改为 `set_spec_text()` 时预计算的 `_spec_w`；缓存失效兜底的 `self._relayout()` 改为 `QTimer.singleShot(0, 延迟重排)` + 本帧不画，并在探针里断言**第 2 帧内容必须恢复**（防「本帧不画」式假修）。
- 60FPS 连带效应：`lyrics.step()` 的每帧收敛系数改为按真实 dt 折算（`alpha = 1-(1-0.22)^(dt/0.033)`），保持每秒收敛率不变（解析解与帧长无关，离散化差 1.2%）。
- 附带：暂停时帧钟不再空转重绘（新增 idle 限速），暂停 CPU 6.25% → 2.6%。

### Task-05 换肤崩溃（Dev 侦察发现，Lead 复核建卡）
`theme.py` 的 QSS 用 `P['popup_bg']` 直接下标，而该键只在 qq-light/qq-dark 定义 ⇒ graphite/amber/sakura/aurora/mint **一切过去就 KeyError**。按项目自己的规矩（QSS 引用到的键必须在基座定义）把键补进基座 + 各深色预设（取各自 `glass_panel` 去 alpha，保证不透明，避免弹层文字穿透），未用 `P.get()` 兜底、未用 try/except 吞异常。

## 2. 团队协作与门禁（本轮的方法论部分）

- **角色分离**：Dev 是唯一写手（只碰 `src/zhijian/ui/{stage,audio_view,theme}.py`）；QA 是唯一守门员（写作用域仅 `build/qa/**`，发现缺陷打回不自修）；Lead 不参与实现，负责拆卡、裁决、终验收与交付。
- **看板协议**：Dev 完成只能 `release`（回到「待审核」），QA `claim` 后独立复验，**只有 QA 能 `complete`**；发现卡不合格由 QA `release` 并附批注。
- **同文件串行**：Task-02/03/04 都改 `audio_view.py`，用 `blocked_by` 强制串行，避免「QA 审的那份被下一张卡覆盖」。
- **Lead 独立门禁**：`build/lead/lead_acceptance.py` 49 项（静态 AST + 真机几何 + 像素 + 回归），支持 `--only` 分节与 `--exe` 直接验打包产物。
- **双臂对照**：QA 把每个卡的冻结修订存进 `build/qa/review_*_src`，HEAD 冻结在 `build/qa/baseline_src`，before/after 同方法同尺寸对照。

## 4. 已知遗留（均不阻塞，供用户决定）

1. **抽屉关闭动画**时手柄在第一帧就跳回最右（展开态逐帧跟随正常）。与 v1.0.34 基线同构、非本轮回归；按卡片字面「收起即贴 W−16」是成立的，若要丝滑需把收起分支也改成 `clamp(抽屉左沿−16, 0, W−16)`。
2. **浅色主题的手柄 1px 收边**退化为 `hairline(#00000014)`；**封面删除投影后为「无投影纯圆角正方形」**。两者都是卡片硬要求下的主动选择，属视觉主观项，建议用户过目。
3. **频谱数据源仍是包络模拟**（能量包络 + 节拍 + 每柱相位 + 对数频段倾斜），**未接真实 FFT/PCM**；本轮的落差与位置问题都已解决，但「频谱与音乐节奏有因果对应」仍未做。
4. 本机 CPU 统计含 mpv/GL，跨轮次噪声大（13%~64%）；建议以后统一用「fresh 实例 + 同协议 A/B + 3 窗口取中位」。
