## 2. 三个「看似无解」的真因（本阶段最大收获）

1. **玻璃发黑的根因不是配色，而是「为了过对比度指标」**：上一版把面板底改成深黑来满足 4.5:1 —— 用户一眼看出「脏黑」。正解是**先把背景模糊掉（消除高频干扰），深色字压在清透白玻璃上照样清晰**：亮度 51.6 → 184.4，对比度仍达标。
2. **歌词截断的根因是「测量与绘制不在同一个尺度」**：`wrap_rows()` 按 27px 测量以保证双态断点一致，绘制却乘 `scale_ratio`。**这类 bug 在小窗口永不复现**（sr<1 时绘制更窄），只有大窗口才露头 —— QA 在默认窗口确实无法复现，如实标注。
3. **PiP 丢失的根因不在 PiP 代码**：`_apply_visibility()` 只有「隐藏」分支没有「显示」分支 ⇒ **任何一次窄窗都会造成永久性丢失**。这是「单向状态机」的典型陷阱。

## 3. 方法论沉淀（本阶段新增 4 条）

1. **窗口边缘/角落/标题栏类判据优先 `m.grab()`** —— 屏幕级抓取会混入 **NVIDIA Overlay** 等外部置顶窗（本阶段再次踩到）。
2. **复验前必须确认场上只有一个实例** —— dev 的白方块截图有一部分是**同屏另一个测试实例窗口**叠上去的。
3. **注入类判据必须充分沉降再采样**（本轮 −8dB 注入后立即采样采到冲击瞬态 p50=72.4%；沉降 2.5s 后才是稳态 42.13%）。
4. **抗锯齿/透明度类改动不能只看数值**：按钮四角「无发黑」是 3× 放大目视 + 四角像素比对共同判定。
