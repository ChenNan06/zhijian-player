## 一、副屏交互失效：先证伪，再定位

### 1. 被证伪的假设：「原生子窗口吃鼠标」

**取证方法**：`WindowFromPoint(POINT)`（纯查询，不动光标）× 14 点 × A/B（无媒体 / 载入视频）。

| 结果 | 说明 |
|---|---|
| **14/14 点全部返回主窗口 HWND** | 类名 `Qt691QWindowOwnDCIcon`、`owns=True`、`exstyle=0x100`（**无 WS_EX_LAYERED / 无 WS_EX_TRANSPARENT**）|
| Qt `childAt/hit_test` 同点解析正确 | IconButton / ProgressSlider / VolumeSlider / _BareSpeedButton / MpvRenderWidget / DrawerHandle |

⇒ **OS 层投递正常、Qt 层命中正常**，「视频原生子窗盖住整窗」不成立。上一版报告的 `video_native: true` 与「整窗子 HWND 659218」是**探针自己调用 `winId()` 造成的假象**（对 widget 调 `winId()` 会强制创建原生窗口）。

### 2. 三个真因

| # | 真因 | 修法 | 实测 |
|---|---|---|---|
| ① | `_restore_geometry()` 用「窗口**当前**所在显示器」的工作区校验保存坐标 ⇒ **任何负坐标（副屏）都被判越界并丢弃**，窗口被拉回主屏 | 改用 `QGuiApplication.screenAt(保存点)` + 相交面积兜底 | config x=-1600 原本落在主屏 `[880,416]`；修后落在 **[-1600,-527]** 副屏 |
| ② | 全仓**没有 screenChanged / DPI 变更处理** ⇒ 主屏 100% 拖到副屏 175% 后，控制栏宿主（绝对定位）、浮层栈、video DPR、圆角遮罩、fader 全停在旧值 | 新增 `_on_screen_changed()`：place_capsule_host / raise_overlays / video.update / drawer·settings·image_bar 布局重算 / drop_overlay 几何 / `apply_handle_geometry`+`sync_hotspots` / PiP 重停靠 / `apply_window_mask` / fader 复位 / `_wake_ui`；触发 = `screenChanged` + `changeEvent` 的 `ScreenChangeInternal` 与 `WindowStateChange` **双路径** | 手动触发后 **drift = [0,0,0,0]**、fader=1.0 |
| ③ | 最小宽写死 **960 逻辑 px > 副屏 914** ⇒ 窗口永远超宽 46px、**关闭键出屏** | `min(960, 可用宽)`，尺寸与位置都夹进 `availableGeometry` | 副屏窗口 **[-1600,-527,914,1180]**、`min_w=914`、关闭键在屏内 |

### 3. 三段式取证结论

| 段 | 判据 | 结果 |
|---|---|---|
| OS 可达 | `WindowFromPoint` 14 点 | **14/14 命中主窗口** ✓ |
| Qt 可命中 | `hit_test` 14 点表 | **7/14 命中预期控件** ✓（余 7 点为标题栏，不属 `stage` 子树，工具限制）|
| 控件可响应 | `QTest.mouseClick` 真实交互 | **3/3**：播放键 `time-pos` 0.292→1.351→2.341；进度条 7.041→13.652；抽屉 `is_open` false→true |

> 合成 `PostMessage` 点击在本机无效（Qt 忽略非可信鼠标消息），故用 `QTest.mouseClick` + `WindowFromPoint` 组合替代；**真实鼠标最终确认由用户完成**。

## 二、播放列表被控制栏遮挡

**根因①**：`raise_overlays()` 抬升顺序是 `drawer_host → capsule_host` ⇒ **capsule 后抬、压住抽屉**。改为 `capsule → drawer → settings → drop_overlay → image_bar_host`。

**根因②**：`stage.py` **四处**单独的 `capsule_host.raise_()`（`place_capsule_host` / `_wake_ui` / `toggle_fullscreen` / showEvent）会在**任意重定位之后**把控制栏又抬回抽屉之上（这就是「明明改了顺序、重叠区却仍看到进度条轨道」的原因）。全部改走 `raise_overlays()` ⇒ 全仓单独 `capsule_host.raise_()` 命中 **0**。

**实测**：z 序 `capsule 11 < drawer 12 < settings 13`；抽屉∩控制栏重叠区 **5/5 `hit_test` 命中抽屉**；触发 `place_capsule_host()` 后**重叠区像素逐位不变**；关抽屉后同点恢复 `ControlBar/VolumeSlider`；设置面板高于抽屉。

## 五、遗留（如实）

1. **`pause / eof / idle` 属性读数不可信** —— 媒体在播时三者都读 true（疑似 engine 缓存未回写）；播放键功能已用 `time-pos` 冻结/恢复证明正常，建议单独开卡；
2. **标题栏不在 `stage` 子树** —— `stage.hit_test` 覆盖不到标题栏 7 点，需用 `m.hit_test` 或 titlebar 树补验；
3. **真实鼠标点击**在本机无法自动化（Qt 忽略非可信消息），最终确认依赖用户手测；
4. 副屏偶尔出现 `GetForegroundWindow()==本窗口`（疑测试期 `grab()`/菜单导致），产品路径未发现主动激活调用。

## 六、方法论

1. **先证伪再下结论**：上一版把「原生子窗盖住」当结论，本轮用 `WindowFromPoint` 直接推翻 —— 并且发现**探针自己调用 `winId()` 会制造出被测现象**（观察者效应）；
2. **多显示器必须做负坐标与 DPI 变更两条链路**：`monitor_work_area(self)` 这类「当前屏」API 用在**恢复保存坐标**上必错；`screenChanged` 不处理，跨 DPI 拖动后整窗状态都会僵在旧值；
3. **`raise_()` 是隐性覆盖**：只要还有一处单独 `raise_()`，任何「顺序修复」都会在某个重定位路径后被推翻 —— 必须**统一收口到 `raise_overlays()`**；
4. **像素与 `hit_test` 冲突时，先怀疑还有别的 raise**（本轮真因②就是这样被 QA 的裁图逼出来的）。
