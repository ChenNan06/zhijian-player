## 一、5 张卡的真因与修法

### ① 视频被缩成 3 行、底部 94px 白条（问题 1）

**用户的证伪**：音量 OSD 胶囊**同样是 Stage 子控件**，它能稳稳浮在视频上；全屏 4 行时控制栏也能浮在视频上 —— 所以「原生子窗口必然盖住」的解释站不住脚。

**真因**：task-103 全屏逻辑把 `capsule_host` 从 `Stage.layout()` 里 `removeWidget` 移除后，**窗口模式的 `Stage.resizeEvent()` 忘了给它 `setGeometry`** ⇒ 只有进出一次全屏、走退全屏分支才拿到坐标 ⇒ 窗口模式首开视频时几何未定，控制栏不可见。

**修法**：删除 `set_video_row_span/_sync_video_row_span` 与全部调用点 ⇒ `video` **永远 4 行 100% 铺满**；新增 `Stage.place_capsule_host()` 统一算式（`setGeometry` + `show()` + `raise_()`，gap 全屏 16 / 窗口 8），挂 `resizeEvent` / **新增 `showEvent`**（0ms/60ms 两帧补摆）/ `_apply_kind_ui` / `attach_capsule`。

**实测（QA 双刀对照）**：`gap` **94px → 0**、`video_bottom == stage_bottom`（759=759）、控制栏**悬浮在视频上**完整可见、进出全屏两轮精确。

### ② 拖动标题栏瞬间变黑 + 桌面模糊不生效 + 掉帧（问题 6、8）

**拖动变黑真因**：task-119 的 `set_acrylic_lite` 在**拖动中动态切换 DWM 属性** ⇒ DWM 把标题栏刷黑并卡顿。

**修法**：**删除 `set_acrylic_lite` 及全部拖动期 DWM 调用**；亚克力**只在创建 + 换肤各设一次**（`DwmExtendFrameIntoClientArea(-1)` → `DWMWA_SYSTEMBACKDROP_TYPE=3` 主路径 → 失败回落 `ACCENT_ENABLE_ACRYLICBLURBEHIND=4`），`_acrylic_path` 记录实际路径。顺手修掉一个吞异常：`_apply_chrome_deferred` 缺 `_theme` 导入 ⇒ `NameError` 被吞 ⇒ **亚克力从来没设上过**。

**掉帧三大杀手**：① 删 `ScrollFeatherEffect(QGraphicsEffect)`（每帧百万像素 CPU 合成）⇒ 改 24px 轻量渐变遮罩；② 抽屉开合/窗口 resize 期间 `freeze_capture(180)` 冻结抓屏与高斯；③ 缩略图完成信号合并 100ms 重绘。

**实测**：`simulate_titlebar_drag` 10 步真移动 162px，标题栏均色 **[32.1→32.8]，drop 2.44%**（阈值 35%）；`_freeze_ms 0→180`、`resize_skips 0→12`；羽化 **p50 = 0.0331ms**（<0.05）；`frame 16ms / QTimer 2`。

**如实边界**：品红背景对照 `delta_r = 0` —— 本机 Win11 24H2 在 frameless + 透明窗下 DWM backdrop 不合成桌面内容（`_acrylic_path="systembackdrop"` 但视觉零贡献）。这条**登记为平台限制**，没有硬凑。

### ③ 音瀑：cmd 黑框 + 双音瀑乱炖 + 无节奏（问题 2、9）

**cmd 黑框真因**：`beatmap.py` 的 `subprocess.run` **没加 `CREATE_NO_WINDOW`** ⇒ 每次切歌弹一个黑色控制台。**修法**：全仓 subprocess 统一 `creationflags=CREATE_NO_WINDOW + 隐藏 STARTUPINFO`，并加 `cmd_spawn_count` 计数。

**双音瀑真因**：旧 `_paint_cascade`（4 轨黑胶囊）与新的 `RhythmStage` **同时存在**且铺满全屏。**修法**：`cascade = None` 停用旧实现；`RhythmStage` **限右侧 180px 窄区**；**删除所有黄/青圆球、粒子、垂直白棒、`COMBO × N` 文字**（grep 全 0）。

**无节奏真因**：音符是「实时检测到声音才生成」，与 BPM 无关。**修法**：对数压缩（Klapuri）+ 能量包络自相关估主拍 + **吸附 `T_beat/2` 网格** + 键型编排（顺楼梯 / 折返 / 重拍双押）+ 同轨 ≥120ms 间隔。

**视觉**：4×40px 半透轨 + 1px α.08 分线 + 1.5px 判定线 + **32×7 圆角 3.5 磨砂胶囊** + 强拍微光边 + 触线 **40px 呼吸光柱 140ms 淡出**。

**实测**：`t_beat 0.45s = 133.3 BPM`、**网格偏差 0.0ms**、四轨 **[24,24,51,24]**（不再全在 lane 0）、同轨最小 **225ms**、重拍双押 28、466→123 合并；`rhythm` **180×712 @[1098,0,180,712]**；连切 5 首 **`cmd_spawn_count = 0`**、conhost **6→6**、`ConsoleWindowClass` 恒 1。

### ④ 歌词亮蓝刺眼 + 双倍间距混乱（问题 3）

**修法**：删掉 `▎` 竖条、原词/译文左缘统一 **x=10**；译文从**亮蓝 (115,210,255)** 改为**同色系明度阶梯**（深 `rgba(235,240,250,.72)` / 浅 `rgba(30,36,48,.68)`）；字号/字重 **26 / 18.5px、700 / 600 / 500**，α **.98 / .54 / .72 / .38**；间距拆两档：**句内 8px / 句间 22px**（原单一 18 废除）。

**实测**：墨迹间距 **[8,8,8,8] / [22,22,22]**；译文 `[235,240,250,0.72]`（无蓝）；`weight 700/600/500`；QA 目视「中性灰、无竖条、左右缘对齐」。

> 口径澄清：QA 读到的 `gap=18 / step_pad=18` 是**折行段落内的行垫**（`lyric.step_pad` 派生），不等于句内/句间间距；**「等距/成组」以渲染墨迹间距为准**。

### ⑤ 抽屉按钮套框 + 选中白字 + 廉价蓝边框（问题 4、5、7）

- 视图切换按钮**删掉外框**（`styleSheet=null`）+ 重绘图标：**▦ 四宫格 / ☰ 三横线**；`1.0x` 与 `词` 改裸字按钮（常态零边框，仅悬停 15% 柔光圆底）；
- 修**选中卡白字**：浅色 正常 `#181C24` / 选中 `#0F62FE`(DemiBold)，深色 `rgba(255,255,255,.85)` / `#58A6FF`；实测对比度 **16.38 / 20.65 / 8.47**；
- 选中态改**现代流光**（无蓝粗描边）+ 左侧 **3×16px 主题色圆角指示柱**（`bar_rect = [904,556,3,16]`、物理 **4.5×24** 实测）。

## 二、本阶段修掉的 5 处「静默吞异常 / 漏导入」——同一个病

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | `audio_view.py` 注释与 `def set_rhythm_enabled` **写在同一行** | 整个方法被注释掉 ⇒ 音瀑永远建不起来 |
| 2 | `playlist_drawer.py` 漏 `QPointF` 导入 | list 态图标**完全空白**（ink 0，修后 144）|
| 3 | `control_bar.py` 漏 `qt_color` 导入 | 新按钮每帧 `NameError`，日志刷满 Traceback |
| 4 | `settings_panel.py` 缺 `QObject` | `class _FeatherSync(QObject)` 崩 |
| 5 | `make_transparent` 被删但 `playlist_drawer` 仍 import | **app 启动即 ImportError（P0，整个程序起不来）** |

**已立两条硬规矩**：

1. **每次改 `src/` 必须跑 import 冒烟**：`python -c "import sys;sys.path.insert(0,'src');import zhijian.ui.main_window"` —— `py_compile` **查不出漏导入与被删符号**；
2. **吞异常一律 `log.warning(..., exc_info=True)`** —— 本阶段 5 处缺陷里有 3 处是因为 `except: log.debug(...)` 而被长期掩盖。

## 四、已知边界（如实登记）

1. **桌面实时模糊在本机不通** —— `_acrylic_path="systembackdrop"`、`_acrylic_on=true`，但品红对照 `delta_r=0`：Win11 24H2 在 frameless + 透明窗上不合成 DWM backdrop。三条独立尝试（SCA=4 / SYSTEMBACKDROP=3 / WindowBody 半透）均零贡献；
2. **125 的品红透光未取证** —— 钩子实际是 `zhijian.platform.win.set_acrylic_probe()`（模块级），QA 找的是 `MainWindow` 上的同名方法；
3. **音瀑 BPM 网格吸附**已达标，但**解码+打分仍 0.3s 量级**（8000Hz 单声道已是最轻路径）；
4. **`lyric.font_px` 默认仍为 27**（设计基准 26）—— 未改，避免动用户已保存配置；
5. **窗口模式视频区与全屏的底栏间距不同**（8px / 16px）—— 按卡面「gap 8/16」实现。

## 五、方法论沉淀（本阶段 3 条）

1. **「技术上不可能」的结论必须先被证伪**：我们用「原生子窗口必然遮挡」说服自己让视频矮 94px，用户一句「OSD 胶囊为什么能浮在视频上」就把结论推翻 —— **先找反例，再下结论**；
2. **`py_compile` 不是冒烟**：漏导入、被注释掉的 `def`、被删的符号都能编译通过，运行时才炸。**import 冒烟必须进流程**；
3. **`except: log.debug` 是本项目的头号杀手**：本阶段 5 处缺陷有 3 处源于此，**吞异常必须 warning + exc_info**。
