## 1. 核心音视频与渲染管线审计

### 1.1 mpv_render_context 与 Qt OpenGL 的绑定方式

调用链（`src/zhijian/mpv/player.py`）：

| 阶段 | 位置 | 实现 |
|---|---|---|
| 建立 | `player.py:602-632` | `makeCurrent()` → 组装 `MPV_RENDER_PARAM_OPENGL_INIT_PARAMS`（`get_proc_address` 走 `_GL_PROC_CB`）→ `mpv_render_context_create` → `doneCurrent()` |
| 更新回调 | `player.py:628-629`, `634-644` | `mpv_render_context_set_update_callback` → 回调里**只调 `self.update()`**（注释明确：绝不在此碰 Qt 控件，跨线程会炸） |
| 每帧渲染 | `player.py:646-700` | `paintGL` 内按 `devicePixelRatioF()` 计算 FBO 尺寸，`defaultFramebufferObject()` 直传 mpv |
| 尺寸变化 | `player.py:658-665`, `732` | **FBO 参数每帧跟随控件尺寸**，无需手工处理 resize —— 这是"resize 不重建上下文"的设计 |
| 全屏切换 | 未在 `player.py` 内特判 | 全屏只是窗口尺寸变化 ⇒ 走同一条 FBO 跟随路径（**本轮未单独实测全屏路径**，见 §6 未验证清单） |
| 释放 | `player.py:744-745` | 先把 update 回调置空（`UPDATE_FN(0)`），再 `mpv_render_context_free` |

> **【2026-10-11 更正】** 本节初版称"释放路径没有显式 `makeCurrent()`" —— **该结论有误**：
> 我只读了 `player.py:744-745` 两行，**漏读了紧邻的 743 行**。实际实现
> （`player.py:736-754` `release_resources()`）**已经**包含
> `_suppress=True → makeCurrent() → 回调置空 → free → doneCurrent()`，
> 并由 `if not self._rc_ready: return` 提供幂等保护。
>
> **真实缺陷是"触发点不完整"而非"实现缺失"**：
> `MainWindow.closeEvent`（`main_window.py:2234`）会释放渲染上下文，
> 但 `finalize()`（`main_window.py:2249`，由 `aboutToQuit` 调用）**只销毁 mpv 实例**，
> 不释放渲染上下文 ⇒ **异常退出路径**（closeEvent 未走到）会留下悬挂的渲染上下文。
> 该缺陷已在 v1.0.12 修复（见 §8）。

### 1.2 已修复的一处关键性能缺陷（值得记录）

`player.py:667-679` 记录了本项目最隐蔽的一次掉帧根因：

> mpv 渲染 API 默认开启 `MPV_RENDER_PARAM_BLOCK_FOR_TARGET_TIME`，
> `mpv_render_context_render()` 会**阻塞到该帧目标显示时刻**才返回 ⇒ GUI 线程每帧被按住
> ~26ms（30fps 时每秒 780ms 不响应）。因为它是**阻塞**而非**忙**，
> 换缩放器/解码/profile/尺寸全部测不出差别（26.0~26.7ms 纹丝不动）。

现已显式关闭（`block = c_int(0)`）⇒ 帧节奏改由 mpv update 回调 + Qt 重绘驱动。

### 1.3 视频表面与 UI 层叠关系

`src/zhijian/ui/stage.py:3` 的注释与实现一致：**单个 `QOpenGLWidget` 跨全部网格行铺满，
三排浮层压在它上面**（Overlay 分层，非多窗口）。

* 浮层包括：标题栏、底部控制栏（胶囊）、图片栏宿主、抽屉手柄、媒体信息浮层、OSD。
* **Overdraw 风险（已更正）**：初版称浮层用 `QGraphicsDropShadowEffect` 做模糊合成 ——
  **该结论有误**：`GlassFrame`（`widgets.py:578-581`）注释明确"阴影由本控件自己在 paintEvent 里画
  （不用 QGraphicsDropShadowEffect）——后者在半透明窗口 + OpenGL 子控件混合时会出现残影与掉帧"。
  且阴影**早已从 16 层降级为单层**（`widgets.py:696-712`），整个背景还被**缓存成 pixmap**
  （`widgets.py:676-685`，key 含尺寸与取色 ⇒ 换肤自动失效）。
  ⇒ 现状的真实开销是"每个浮层各自缓存一张背景 pixmap"的**内存**（而非每帧 CPU 模糊）。
  v1.0.12 已按用户指令把浮层投影**整体关闭**（`_GLASS_SHADOW_ENABLED = False`），
  形体改由 1px 物理像素对齐描边承担。
* **撕裂**：本项目**未启用 vsync 特判**（`app.py:232-234` 注释说明只给视频控件 `setFormat()`
  不足以控制最终上屏节奏）⇒ 高帧率素材下**存在撕裂可能**，本轮未做量化观测。

### 1.4 探针实例与主实例的参数隔离

`src/zhijian/media/prober.py` 采用**独立实例**（`t.join(timeout)` 于 `prober.py:58`）。
**未验证**：探针实例的 `--profile` / 硬解 / 缓存参数是否与主实例完全隔离（本轮未逐项比对）。

## 7. 最亟需重构/优化的 Top 5 技术债

### T1｜双份 FFmpeg：打包体积 63% 花在同一件事上
`libmpv-2.dll`（116.1 MB，内含 FFmpeg 全量）+ `imageio_ffmpeg`（83.6 MB）= **199.7 MB / 316.6 MB**。
缩略图抽帧完全可以复用 libmpv 自身的解码能力（`--vo=image` 或独立 mpv 实例抓帧），
或至少共用同一份 FFmpeg 二进制。**预计可缩减 ~80 MB（-25%）**。
> 影响：分发体积、冷启动 IO、安装时间。

### T2｜渲染上下文生命周期未加固（悬挂风险）
`player.py:744-745` 释放前无 `makeCurrent()`；mpv 要求 free 时上下文 current。
建议：封装 `destroy_render_context()`，内部保证 `makeCurrent() → free → doneCurrent()`，
并在 `aboutToQuit` 与窗口 `closeEvent` 双路径调用、加幂等保护。
> 影响：偶发崩溃/退出挂起，且**难以复现**。

### T3｜没有自动化回归套件（最大工程债）
现有验证手段是 `build\` 下的**一次性探针脚本**（本轮新增十余个），它们：
* 不在仓库内（`.gitignore` 排除 `build/`）、不随提交运行、无统一入口；
* 判据写法五花八门，**本轮就出现 5 次"判据本身写错导致误判"**（颜色容差、控件类型、
  坐标空间、阈值过严、缺键跳过）。
建议：把探针收敛为 `tests/` + `pytest`，封装统一的"应用内断言库"
（启动、IPC、真实输入、像素判据），并在每次打包前自动跑一遍。
> 影响：**每一轮修复都可能悄悄弄坏别的功能**（本项目已多次发生）。

### T4｜主题广播靠隐式整树重放，缺闸门
显式注册仅 5 处，新控件若漏实现 `on_theme_changed` 会**静默不跟随主题**。
建议：像 `audit_surfaces()` 那样加一个**主题合规闸门**（启动时遍历自绘控件，
断言其声明了主题回调或注册进 `themed()`），纳入打包前检查。

### T5｜退出收尾的多级超时串联，缺总预算与可观测性
`wait(2500)` + `communicate(timeout=12)` + 若干 `join(timeout)` 串联，
最坏情况退出被拖到十几秒，且没有"谁拖慢退出"的输出。
建议：设总预算（如 3s），超预算即强制 `terminate/kill` 并**记录到日志**；
把退出各阶段耗时打进 `zhijian.log`，便于用户反馈时定位。
