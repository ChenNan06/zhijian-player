## 一、Task-133 P0：QRegion 黑块/重影/左栏丢失（紧急止血）

**真机灾难**：音乐模式中央巨大黑块，歌词/设置面板文字/拖放提示无限叠印乱码，左栏歌名/歌手/专辑/规格全部消失。

**真因**：Stage-18 给 `audio_view._paint_bg` 补了 `QRegion` 导入，激活了错误裁剪：
```python
reg = QRegion(0,0,w,h).subtracted(core_dst)
p.setClipRegion(reg)
p.fillRect(...)          # 只画核心区以外
p.setClipRegion(QRegion())   # QRegion() 是**空区域**，不是"复位"！
```
`setClipRegion(空)` 把 `_paint_bg` 之后的所有绘制（核心图/遮罩/左栏四行/歌词）全部裁掉；`AudioView` 是 `WA_OpaquePaintEvent`，Qt 不擦帧缓冲 ⇒ 核心区不重绘、旧画面叠印成黑块与乱码。

**修法**：删除 `_paint_bg` 全部 QRegion 背景裁剪与导入；`p.fillRect(0,0,w,h)` 全幅重绘；审计全文件 3 处裁剪（CoverArt 的 setClipPath/setClipping 配对、LyricsPanel 独立缓冲 painter 的全矩形裁剪）均正确。

**实测**（offscreen，修复前 → 后）：

|---|---|---|
| 中央核心区近黑像素占比 | **89.54%**（144693/161595） | **0.00%** |
| 左栏四行（歌名/歌手/专辑/规格）纯黑像素 | 1800/1050/1050/1050 | 0/0/0/0 |
| 左栏四行墨迹 px | 被黑块遮蔽 | 836/288/288/792 |
| 真机场景（播放→开关设置→滚歌词 10 帧）中央黑占比 | — | **0.0 / 0.0**（AudioView/窗口） |
| 关设置面板后与基线差异 | — | mean 1.35（仅进度/频谱动画），无叠印残留 |

## 二、Task-134 P0：深色抽屉曜石深底 + 冷启动不自动展开 + 手柄对齐

**真因**：`playlist_drawer` 写死 `GLASS_FILL_DRAWER=#FFFFFF8C`（`GLASS_DARK_FILL` 定义未使用）⇒ 深色主题抽屉是白底（实测亮度 169.82）；`app.py:536` 启动时按 `ui.drawer_open` 恢复展开 ⇒ 冷启动乱开；首次布局未稳定就计算手柄 ⇒ 错位。

**修法**：
- 抽屉底板按 `theme.is_light()` 动态取色：浅色 `rgba(245,248,255,0.58)` + 冷灰细边；深色 `rgba(18,22,30,0.68)` + **仅左侧** 1px `rgba(255,255,255,0.14)` 边框；文字/卡片同步（深色 #F0F4F8/#58A6FF、选中底衬 `rgba(56,152,255,0.18)`；浅色 #181C24/#0F62FE）；新增 `on_theme_changed()` 换肤立即刷新；
- 删除 `app.py` 启动恢复 `ui.drawer_open` 的分支；`config` 默认 False 保持（仅记录不恢复）；
- `showEvent` / `open_path` 末尾 / `_apply_kind_ui` 末尾补 `QTimer.singleShot(0, stage.sync_handle_geometry)`；`_on_anim_done` 延后一帧补发宽度，消除展开态 1px 偏差。

**实测**：

## 七、方法论沉淀

1. **"补上 import"也可能是灾难**：Stage-18 把"漏导入被 except 吞掉"当成 bug 修，结果激活了错误裁剪逻辑。修静默异常时必须先确认被吞掉的那段代码本身是否正确。
2. **QRegion() 不是"无裁剪"**：`setClipRegion(QRegion())` 会把绘制裁到空；复位应使用 `setClipping(False)` 或 `save()/restore()`。
3. **QA 的 before 证据是这次止血的关键**：中央黑块 88.34%、左栏 0/4 可见、抽屉亮度 169.82 全部量化存证，修复后逐项对照。
4. **"源码修好 ≠ 交付物修好"**：打包版仍需 --probe + 控制面 + 打包版真实谱面复验。
