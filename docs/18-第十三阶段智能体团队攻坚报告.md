### Task-92 · P0 标题栏原子重绘（用户问题 3 / 4 / 7）

**现象**：标题栏底色在纯白/深灰/透明之间乱跳；鼠标移到右上角月亮/齿轮或左上角 `...` 上时，按钮所在矩形区域爆出白色或深灰方块；左上角 `...` 展开菜单时蓝圈左上侧被削平。

**根因（两条，第二条是排查出的关键）**：

- ① 子按钮在**不一致的帧缓冲**上局部擦写 —— 标题栏是复合图层，子按钮单独重绘时背景失步；
- ② **玻璃分支对「标题栏正下方舞台」做实时模糊采样**，但标题栏位于视频区上方，采样矩形落在舞台**外**，取到的是随视频帧变化的边缘行 ⇒ 背景随视频乱跳。

**修法**：TitleBar 把 6 个子按钮登记为 owner，任何 `enter/leave/悬停动画每帧/checked/pressed` 都**强制整条标题栏重绘**；子按钮常态零背景，悬停只画中心圆（32×32 内 r=11、圆心 (16,16)、四周 5px 净空）；背景改为**确定性 `bg_base` 实底**（玻璃再叠白琉璃层），与视频帧无关。

**真机证据**：

| 判据 | 实测 |
|---|---|
| 三主题悬停往返后 `titlebar.grab()` 与基准逐像素差 | **changed_gt6 = 0 / max = 0 / bbox = null**（qq-dark / qq-light / glass-light 全部） |
| checked 态蓝圈 | **22×22 实心正圆、360° 完整、无削边、三点居中**（Lead 亲验三主题 7× 放大图） |
| 开/关菜单时底色 | qq-dark / qq-light 跳变 0；glass ≤5/255（**未定论，见第五节**） |

### Task-93 · P0 废除 1-bit setMask，改 DWM 原生圆角（用户问题 4）

**现象**：窗口四角有**明显像素锯齿与暗影**。

**根因**：task-85 用的 `QWidget.setMask()` 是 **1-bit 二值硬遮罩**，只能「有/无」不能抗锯齿。

**修法**：彻底移除 `setMask()`（`clearMask()` 清残留）；Win11 走 `DwmSetWindowAttribute(hwnd, DWMWA_WINDOW_CORNER_PREFERENCE=33, DWMWCP_ROUND=2)`；Win10 回退用 `QPainterPath` 抗锯齿圆角 + `CompositionMode_Source` 擦净；全屏/最大化用 `DWMWCP_DONOTROUND`；换肤 / resize / show / 退全屏四处重算。

**真机证据**：

| 判据 | 实测 |
|---|---|
| 是否还有 mask | `bool(w.mask()) == False` |
| DWM 分支 | `dwm_state()` 三态（normal / maximized / fullscreen）全为 `{mask:false, fallback:null, dwm_ok:true}` |
| 四角观感 | 控件级 3× 拼图：圆润平滑无阶梯锯齿；圆角外**透明而非灰黑** |
| 最大化是否露角 | **屏幕级 BitBlt** 底部两角：画面填满、无桌面三角、无灰黑溢出 |

> **方法论边界**：`m.grab()` 渲染的是控件自身绘制（自带圆角透明区）⇒ **分不清 DWM 窗口级圆角**；「窗口角上是否透出桌面」**必须屏幕级抓图**。

### Task-94 · P0 玻璃模式黑滚动条 / 黑开关净化（用户问题 1）

**现象**：清透洁白的液态玻璃设置面板里，右侧滚动条是一根**纯黑粗棍**，右下角开关是**纯黑底色**。

**修法**：

- `QScrollBar`：滑槽透明；滑块**宽 6px、圆角 3px**、`rgba(120,132,150,0.32)`，悬停 `rgba(100,112,130,0.52)`；
- `ToggleSwitch`：**OFF** 轨道 `rgba(145,155,170,0.35)` + `1px rgba(255,255,255,0.55)` 高光边 + 纯白圆球 + 微投影；**ON** 轨道 `rgba(56,152,255,0.78)` + `1px rgba(255,255,255,0.65)` 高光边 + 纯白圆球。

**真机证据**：玻璃模式滚动条 `black_lt40 = 0`、`black_lt60 = 0`，`min` 亮度 **130.5**（面板底 ≈245）；开关 OFF/ON 两态 `black_lt40 = 0`；深色主题不回归。

> **方法论边界**：**玻璃控件 `grab()` 返回全黑**（透明合成问题）⇒ 玻璃类证据必须用**屏幕抓图**。

### Task-96 · P0 PiP 尺寸污染（用户问题 8）

**现象**：在 PiP 小窗（480×270）下直接关闭程序，下次启动主窗口**变成 480×270 巴掌大小**。

**根因**：`closeEvent()` / `_store_geometry()` 保存窗口宽高时**未检查是否处于 `_in_pip`**，把 PiP 尺寸写进了 `config.json`。

**修法（双重防污染）**：

1. **保存侧**：若 `_pip` 且存在 `_pip_saved_geo` ⇒ 写回**进入 PiP 前的矩形**（宽高 + 位置）；`ui.maximized` 在 PiP 下不置 True；
2. **读取侧**：冷启动夹取 `w = max(960, cfg_w)`、`h = max(640, cfg_h)` ⇒ 历史已污染配置也能自愈。

**端到端实测**（隔离 APPDATA + 读 `config.json` 原文）：

| 段 | 操作 | 结果 |
|---|---|---|
| a | 启动 | 1280×760 |
| b | 进 PiP | **480×270**（复现污染源） |
| c | **PiP 下直接 quit** | config `ui.window_w/h = **1280×760**`（非 480×270） |
| d | 重启 | **1280×760**（≥960×640） |
| e | 人工把 config 改成 480×270 再启动 | **自愈 960×640**，并改写回 960/640 |
| f | 正常关在 1100×700 ⇒ 重启 | **1100×700 逐位保留** |

> **方法论**：config 是**分节**的，尺寸在 `ui.window_w / ui.window_h`（不在顶层）；补丁脚本**只改白名单键**，否则会误伤 `drawer_width` / `capsule_autohide_ms`。

### Task-97 · 歌词字体与投影（用户问题 7 / 9）

**现象**：双语歌词未唱中文行一坨黑一坨浅、粗细不均；小字后排糊成黑团。

**两个真因**：

1. **浅底深字仍画 2px 黑影** ⇒ 深色小字 + 黑影 = 密集汉字糊成黑团；
2. **GDI 网格对齐（Hinting）** ⇒ 60FPS 滚动时 Y 为浮点，相邻两条横画一条占 2px（巨粗）一条占 1px（巨细）。

**修法**：

- `LyricsPanel` 全部歌词字体施加 `setStyleStrategy(PreferAntialias | PreferQuality)` + `setHintingPreference(PreferNoHinting)`；
- 亮底深字（`_dark_text_on_light()`，浅色/亮玻璃按底色亮度 >150 判定）**强制零阴影、单层矢量直绘**；深色白字保留极柔底影。

**自引入回归（自检发现并修复）**：`_dark_text_on_light` 被**误挂在 `@staticmethod` 下**（插入位置正好在装饰器与 `_tune_font` 之间）⇒ `self._dark_text_on_light()` 抛 `TypeError: missing 'self'` ⇒ `_rebuild_shadows()` **在取 alpha 之前就崩** ⇒ 表现是「深色投影恒空 + 开关无效」。

**真机证据**：

| 判据 | 实测 |
|---|---|
| 浮点 Y 一致性 | Y = 100.3 / 100.7 / 101.1 / 101.5 / 101.9 ⇒ 墨迹像素数 **334 × 5 全等**、竖笔画中位宽全等 |
| 真机浅色 | 3 个滚动位置 3× 放大：笔画一致、无黑团、无重影 |
| 投影修复 | `_shadow_main = 4`；qq-dark 开/关差分 **changed_gt3 = 68 / max = 4（极柔）**；浅色开/关差分 **0**（不回归） |

## 四、方法论沉淀（7 条，已入 QA 基线）

1. **`m.grab()` 分不清 DWM 窗口级圆角** ⇒ 「窗口角上是否透出桌面」必须**屏幕级**抓图；
2. **玻璃控件 `grab()` 返回全黑** ⇒ 玻璃类证据必须屏幕抓图；
3. **按钮「背景差」先看 alpha** ⇒ 透明底 RGB 全 0 会得到「假一致」；
4. **角度桶覆盖率对细条是假阳性** ⇒ 判「环形」看**外接框形状**；「蓝圈」类判据必须区分 **hover 色变 vs checked 蓝底**，且在目标状态保持中抓图；
5. **config 分节**，尺寸在 `ui.window_w/h`；补丁脚本**只改白名单键**；
6. **eval 只吃表达式**（语句静默丢弃）、**无 `dir()`**（用 `vars(obj)`）；注入类判据**必须等沉降 >2s** 再采稳态；
7. **新方法插入类体时装饰器归属必须核对**（`type(getattr(Cls, name))`）—— 本次 `@staticmethod` 被新方法吃掉，症状却是「深色投影消失」，把排查引向绘制段绕了一大圈。

**本轮新踩并留下的工具边界**：

- **模态菜单会阻塞 IPC**（`eval` 直接 Timeout）⇒ 验证模态期间状态必须 `QTimer.singleShot` 预埋动作；
- **`mapToGlobal ± 猜测边距` 不可靠** ⇒ 屏幕抓图要用**控件自报的权威矩形**，并先验证框内确有目标内容；
- **setter 之后必须回读校验**：`IconButton.set_checked(True)` 会被状态同步复位（读回 `_checked=false`），正确锚点是 `set_checked(bool)`（下划线风格，非 `setChecked`）。
